One line per surprise: date, engine, model, what happened, what check it became.
- 2026-11-08, kapitsa 0.2.31, qwen3.8-27b: the server keeps a prefix cache on the SSD across requests and restarts, so a second run's "cold" prompts, byte-identical to the first run's, came back fully cached: TTFT 0.3 s and a nonsense reading rate. Check: a random nonce right after the system tag on every cold prompt (Kapitsa bench's own rule), and a cold prompt that reports more than 16 cached tokens makes the run INVALID.
- 2026-11-08, kapitsa 0.2.31, qwen3.8-27b: asked to write the 512-token LRU-cache module on top of a repository conversation, the model stopped after 18 to 110 tokens in 6 of 15 runs (finish_reason=stop), and when it did write, the drafter accepted fewer tokens than on the short "code only" prompt (3.6 vs 5.3 tokens per step), so "writing at depth" mixed a text-type effect with a depth effect. Check: the depth prompt says the task is unrelated and asks for code only, a run counts only if it reaches max_tokens, up to two extra attempts, and the row prints how many runs were valid.
- 2026-11-08, kapitsa 0.2.31, qwen3.8-27b: 3 of 20 tool trials were scored invalid because the model called read or glob before an edit, which is correct agent behaviour. Check: validity is well-formedness (structured call, known tool, JSON arguments, right types); an unexpected tool is reported as a note.
